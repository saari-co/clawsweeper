# Native review telemetry status proof

The actual publisher CLI reads controlled synthetic host records, writes its
feed, and the actual Bay consumer normalizes that feed. The result records the
publisher source hash and observed states. An earlier clean OpenClaw attempt
followed by a watchdog failure remains unknown. Marker-like title text cannot
supply a native verdict. A report generated by the real native document renderer
with a finding projects the canonical publication verdict (blocked), without
requiring a verdict marker inside the stored report.

Run the publisher after building the engine: it imports the canonical native
comment renderer from `dist/clawsweeper.js`. No separate readiness policy is
implemented in the observer. The regression tests exercise these same integration
boundaries in `test/publish-saari-review-telemetry.test.ts`.

This is local CLI/consumer proof with synthetic records, not a deployment or
live-queue proof. Bay is affected only in its observer status projection; no
schema, mutation controls, or merge authority change.

The additional `publication.json` records the actual exact-tuple validator CLI
accepting the rendered report's body digest and rejecting a changed live digest.
The digest is authored from the native context's primary body, including the
upstream compacted-body source identity. The same proof executes the workflow's
actual cleanup shell on owned synthetic directories: its own checkout is removed,
a neighboring run survives, and a symlink is refused. No live runner cleanup is
performed. The publisher regression also verifies that the bounded feed selects
fresh observations before historical rows.

The CLI proof also keeps a newer attempt fresh when its native artifact is older,
and exits nonzero for a missing input root instead of publishing a healthy empty
feed. A row's observation time is the latest valid observation across its lanes;
it does not upgrade either lane's verdict.
