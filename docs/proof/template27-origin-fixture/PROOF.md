# Template Store origin rejection fixture

This candidate qualifies only the complete source line in Template Store PR27
that rejects a credential-bearing Payments origin. It adds two exact attribution
rows for the observed URI detector's PLAIN and HTML outputs and admits that exact
test path/decoder pair to the attribution schema. It adds no generic value or
file allowlist and does not change the product fixture.

## Inspection basis

An explicitly approved offline inspection bound the original line and native
match to their recorded SHA256 identities. The complete URI consists only of
predeclared generic public placeholder credentials and a reserved/loopback host,
with an ordinary HTTP scheme, root-only path, no port, query, fragment or encoded
payload. `neutrality.json` records all component checks, reviewer and timestamp.
This is a direct non-sensitive component assessment independent of scanner
verification status and test intent. It does not assert historical authorship.
No literal or credential value was written to prompts, logs or proof artifacts.

## Real behavior proof

The built engine's existing `resolvePatchWitnesses` bound the HTML observation
at patch line2275 to head blob `5fcd90782012a463f76c3d4e2ef2e2bec02dc47f`,
source line154 in `tests/unit/checkout-host-wake-client.test.ts`, mode100644.
`witness.json` records this and six rejected witness mutations. A preliminary
hunk mutation accidentally altered an unrelated section; the final check alters
the fixture's own hunk and correctly refuses it.

The existing native-worker proof observer ran the complete committed source range
with TruffleHog3.97.4, unchanged scanner flags and returned bytes, Node24.18.0,
a cleared environment and bubblewrap network isolation. Baseline engine
`0ec81c473eba98f1e5bf2ed2b40b7f253a928233` refused both findings; the isolated
candidate admitted them. `before.json` and `after.json` retain source, scanner,
staged-input and native-match identities. Network isolation prevents live
credential verification; normal runtime verification behavior is unchanged.

The original observer attempt encountered PATH's older3.97.1 and stopped before
scanning. Selecting the already-installed pinned3.97.4 resolved that prerequisite;
no scanner was downloaded or reconfigured.

`classifier.json` exercises the actual baseline/candidate classifiers with the
hash-bound fixture held only in memory. It proves both decoder paths separately,
rejects verified status, unsupported decoder, altered Raw/RawV2, duplicates,
incomplete scan and mixed unqualified finding, alongside the witness mutations.
Portable tests use a different public synthetic fixture and an injected exact
attribution, testing real Git add/remove/context patches without reproducing the
inspected value in the test source.

## Limits and activation

This is isolated preparation, not installed policy. No model review of the
product, published clearance, product merge, deployment or live retry occurred.
After qualified review and explicit policy activation approval, the receiver
must select a new immutable engine pin and perform its own complete-input scan.
The current product remains blocked until that native review succeeds.
OpenClaw Bay is unaffected: no observer schema or user interface changes.

Focused validation: all462 `agent-input-scan-fixtures.test.ts` tests pass on the
isolated Spark-2 candidate, including both new decoder regressions. This is
supporting evidence alongside the real native before/after observations above.
